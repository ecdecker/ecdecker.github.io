This page is deliberately long. The publication layout is only interesting past
the point where a reader has to scroll — measure line length, heading rhythm and
plate spacing on three paragraphs and everything looks fine.

It also sets `images.onDemand: true` in front matter, so every plate after the
first is wrapped in a closed `<details>`. That is the one reliable
JavaScript-free way to guarantee nothing below the fold is transferred: content
inside a closed `<details>` is `display: none`, which Chrome, Safari and Firefox
all honour by not fetching the image at all. The default lazy path is covered on
[the image exercises](../images/); this page covers the other mode, and pairing
them here is deliberate — a long article for a metered audience is exactly where
the trade of a click per plate buys the most.

![A soft curve of paper against a plain ground](images/paper-curves.png "Plate I — Curves, eager")

The plate above is `.Ordinal 0` and stays eager and outside the `<details>`
wrapper. It is the likely LCP element and would be fetched at load regardless.

## Why the threshold matters

Lazy loading is weaker than it appears. Chrome's distance-from-viewport
threshold is 1250px on 4G but 2500px on 3G and slower, which inverts the
intuition: the readers with the least bandwidth prefetch the most. On a
twenty-plate article that is four plates at startup rather than two.

> The research involves developing nations, and it would be rude to eat up all
> their bandwidth for site inefficiencies.

That constraint is the reason this mode exists at all. It is off by default
because a click per plate is a real cost to a reader on a fast connection, and
on by page for the articles where it is not.

### Heading depth

This is an `h3`, nested under an `h2`, under the page `h1` supplied by the
layout. Depth is worth exercising because the scale compresses fast: display
type runs to 96px while `h3` sits near body size, and the gap is carried by
weight and spacing rather than size alone.

## Code and inline marks

Inline code such as `--space-2xl` sits in the body without breaking the line
rhythm. Fenced blocks scroll rather than wrap, because wrapped code lies about
where the line ends:

```go-html-template
{{- $usable := slice -}}
{{- range $widths }}
  {{- if le . $img.Width }}{{ $usable = $usable | append . }}{{ end }}
{{- end }}
{{- if not $usable }}{{ $usable = slice $img.Width }}{{ end }}
```

That fragment is the upscale guard from `_partials/image.html`, which is
verified against a 240-pixel source on the image exercises.

## Footnotes

Footnotes are worth exercising because they generate their own link structure
and back-references, which is exactly the sort of markup a render hook can
break without anyone noticing.[^1] A second one confirms the ordering and the
return arrows.[^2]

[^1]: The link hook passes bare fragments straight through, so a footnote
    reference stays a fragment rather than being resolved as a page resource.

[^2]: The back-reference is generated by Goldmark, not by the theme.
