{{- /* Markdown image render hook. Lets authors write plain markdown — ![Alt text](plate.png "Optional caption") — and get AVIF/WebP responsive output with no shortcode syntax in the content file. Images stay ordinary markdown, which matters for a corpus that is mostly images with prose between them. Resolution order: page-bundle sibling first, then assets/. Research posts are page bundles with their images alongside the text, so the sibling lookup is the common case. DESIGN.md forbids captions overlaid on images, so a markdown title becomes a figcaption beneath the frame instead. Startup transfer ---------------- .Ordinal 0 is the first image in the document. On an article it sits just below the header, inside the initial viewport, so it is fetched at load no matter what loading= says. Marking it eager with a high priority does not add a request — it reorders one that was already going to happen — and it is the likely LCP element. Every later plate stays lazy. Note that lazy is weaker here than it looks: Chrome's distance-from-viewport threshold is 1250px on 4G but 2500px on 3G and slower, so the readers with the least bandwidth prefetch the most. Measured on a 20-plate article that is 4 plates (41 KB) at startup rather than 2 (32 KB). On-demand mode -------------- Set images.onDemand = true (site params, or per page) to wrap every plate after the first in a closed
. Content inside a closed
is display:none, which Chrome, Safari and Firefox all honour by not fetching the image at all — the only reliable JavaScript-free way to guarantee nothing below the fold is transferred. The cost is a click per plate, so it is off by default and worth enabling only for audiences on metered or very slow connections. */ -}} {{- $dest := .Destination -}} {{- $page := .Page -}} {{- $res := "" -}} {{- /* Page-bundle sibling */ -}} {{- with $page.Resources.GetMatch $dest }}{{ $res = . }}{{ end -}} {{- /* Global assets/ */ -}} {{- if not $res }}{{ with resources.Get (strings.TrimPrefix "/" $dest) }}{{ $res = . }}{{ end }}{{ end -}} {{- $first := eq .Ordinal 0 -}} {{- /* Page front matter wins over the site default. */ -}} {{- $onDemand := false -}} {{- with site.Params.images }}{{ if isset . "ondemand" }}{{ $onDemand = .onDemand }}{{ end }}{{ end -}} {{- with $page.Params.images }}{{ if isset . "ondemand" }}{{ $onDemand = .onDemand }}{{ end }}{{ end -}} {{- $defer := and $onDemand (not $first) -}} {{- /* .post-body is capped at 64ch, so above that breakpoint the slot is fixed and there is no reason to fetch a wider variant. */ -}} {{- $sizes := "(min-width: 880px) 640px, 100vw" -}} {{- /* Full-resolution on request. The ladder tops out at 640px because that is the widest the plate is ever drawn, which is right for reading and wrong for looking closely at a plate — the whole point of this corpus. So each plate gets a link to a bigger encode, placed after the figure and never fetched until it is clicked. Transfer stays opt-in, which is the only version of "full resolution" that is defensible on a metered connection. Capped at 1600px, NOT the original. Two reasons, one of them a landmine: build.publishResources = false means an original is written only if something calls .RelPermalink on it, and doing that here would silently republish every source PNG — the exact 13 MB regression c7f5a07 removed. This calls .RelPermalink on a derivative only; the source is read for .Width, which publishes nothing. The second reason is that the cap is where the bytes are: for editorial-workspace (2688x1792) the ladder runs 1600w 120167 B, 2048w 192677 B, native 313013 B against an 8.2 MB PNG. 1600px is past retina for a 640px slot and 2.6x cheaper than native. q60 rather than the measured per-image q, because the measured value is tuned to hold SSIM 0.92 at the 800px delivery width. Someone who clicked through is looking for detail, and the request is already explicit. The weight is stated in the link, reusing the fileMeta/unit keys that render-link.html already uses for downloads — a reader on a prepaid bundle gets to decide with the number in front of them. */ -}} {{- $full := "" -}} {{- $fullMeta := "" -}} {{- if $res -}} {{- $cap := 1600 -}} {{- if lt $res.Width $cap }}{{ $cap = $res.Width }}{{ end -}} {{- /* Only worth offering if it is meaningfully bigger than the widest variant the plate already ships. */ -}} {{- if gt $cap 640 -}} {{- $t := try ($res.Resize (printf "%dx avif q60" $cap)) -}} {{- /* Same guard as image.html: a failed AVIF transform leaves a zero-byte cache entry that reads back as success on the next build, so an empty payload is a failure, not a result. A plate that cannot be encoded simply gets no link. */ -}} {{- if and (not $t.Err) (len $t.Value.Content) -}} {{- $full = $t.Value -}} {{- $bytes := len $full.Content -}} {{- $size := "" -}} {{- if lt $bytes 1024 -}} {{- $size = printf "%s %s" (lang.FormatNumber 0 $bytes) (T "unitBytes") -}} {{- else if lt $bytes 1048576 -}} {{- $size = printf "%s %s" (lang.FormatNumber 1 (div (float $bytes) 1024.0)) (T "unitKilobytes") -}} {{- else -}} {{- $size = printf "%s %s" (lang.FormatNumber 1 (div (float $bytes) 1048576.0)) (T "unitMegabytes") -}} {{- end -}} {{- $fullMeta = T "fileMeta" (dict "kind" "AVIF" "size" $size) -}} {{- end -}} {{- end -}} {{- end -}} {{- if $defer }}
