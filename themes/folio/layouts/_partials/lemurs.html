Anchoring to the article would put most of the loop below the fold, and make the border-hugging climb cover that whole length in the same few seconds — fast enough to read as a glitch rather than a climb. Opt in per page with `lemurs: true` in front matter — called only from page.html, and only under that guard, so no other page pays any byte for it. That mirrors how images.onDemand is scoped in render-image.html. Pure CSS, no JavaScript, matching the rest of the theme. Two independent animations run on the same element: lemur-journey moves it around the header (left/top), tilts it during the hang (transform), and swaps which action's sprite strip is showing (background-image) at each stage. lemur-frames steps background-position-x through that strip's 6 frames on its own short loop, the classic CSS spritesheet run-cycle trick. It is deliberately not synced to lemur-journey's stage changes — like a looping GIF, it only needs to keep reading as motion, not to land on a particular frame at a particular instant. Each stage below restates every animated property (left, top, transform, opacity, background-image) rather than only the one that changed. background-image is a discrete (non-interpolable) property: left unspecified at a keyframe, its value flips at the midpoint of whatever gap surrounds it, which reads as an arbitrary early or late costume change.
